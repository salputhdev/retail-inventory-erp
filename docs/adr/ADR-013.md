# ADR-013 — Autentikasi web: Fortify, sesi, dan pencatat audit

| Item | Detail |
| ---- | ------ |
| Status | Diputuskan di T1.03 (menunggu merge PR oleh Salman) |
| Tanggal | 6 November 2026 |
| Terkait | Architecture §5; PRD US-1.22, S-03, S-04; ADR-003 |

## Konteks
Login harus aman (R4) sesuai S-03 (password ≥ 12 karakter + cek bocor, lockout 5 gagal/15 menit) dan S-04 (idle 30 menit, absolut 12 jam). Fortify menyediakan alurnya, tetapi beberapa bawaannya tidak memenuhi requirement.

## Keputusan
| Topik | Keputusan | Alasan |
| ----- | --------- | ------ |
| Registrasi | Mati. User dibuat admin (T1.08) | US-1.24 |
| Throttle | `LoginRateLimiter` diganti: 5 **gagal** per email+IP dalam **15 menit**, ditambah 20 gagal per IP | Bawaan Fortify: jendela 1 menit; throttle di route menghitung semua request |
| "Ingat saya" | Dimatikan (parameter diabaikan, tidak ada cookie recaller) | Cookie jangka panjang memicu event login ulang dan melewati batas absolut 12 jam |
| Umur sesi | Middleware `EnforceSessionLifetime`: idle (`auth.idle_timeout_minutes`), absolut (`auth.absolute_timeout_minutes`), sesi tanpa jam ditolak | Tidak bergantung pada TTL driver; bisa diuji dengan manipulasi waktu |
| Pencabutan sesi | User dinonaktifkan atau `password_changed_at` lebih baru dari login = sesi dicabut di request berikutnya | Sesi disimpan di Redis; tidak ada daftar sesi per user |
| Anti-enumerasi | Pesan login gagal sama untuk email tak dikenal/password salah/nonaktif; hash selalu dicocokkan (hash palsu bcrypt); "lupa password" selalu menjawab sama | Mencegah penebakan akun lewat pesan atau waktu respons |
| Password | `PasswordRule`: min 12 + `uncompromised()` (k-anonymity, HIBP). **Fail-open** bila layanan tak terjangkau | Ketersediaan login; panjang minimum tetap ditegakkan |
| Audit | Kontrak `AuditTrail`; implementasi sementara `LogAuditTrail` (channel `audit`, 365 hari). **T1.07 menggantinya dengan tabel yang tidak bisa diubah aplikasi** | Tabel audit baru ada di T1.07; pemanggil tidak berubah |
| Redaksi | `Redactor` menyamarkan kunci berisi pass/token/secret/code/key/cookie | Password tidak pernah masuk audit |

## Konsekuensi
- Kriteria T1.03 "tercatat di audit log" dipenuhi lewat kontrak + channel log; persistensi tak-terubah menunggu T1.07 (ISS-019).
- Email di database harus disimpan huruf kecil (pencarian sudah tidak peka huruf, tetapi unik-nya belum): ISS-020 untuk T1.08.
- 2FA dan passkey (T1.05) menambah langkah pada pipeline login dan harus mempertahankan: remember mati, throttle 2FA, dan pesan generik.
