# ADR-006 — Hosting, backup, dan PITR

| Item | Detail |
| ---- | ------ |
| Status | **Diputuskan sebagian (6 November 2026):** staging memakai Docker lokal prod-like; VPS dilewati. Hosting produksi nyata belum diputuskan. |
| Tanggal | 6 November 2026 |
| Terkait | Architecture §9; task T0.02 |

## Konteks
NFR B-01..B-03 menuntut RPO ≤ 15 menit, RTO ≤ 4 jam, retensi ≥ 30 hari. Ini proyek portfolio, jadi infrastruktur riil dibatasi satu VPS.

## Opsi
1. VPS (Hostinger) + PostgreSQL sendiri + pgBackRest/WAL-G
2. Managed PostgreSQL di cloud (AWS RDS, GCP, Azure)
3. PaaS

## Keputusan
Usulan: **VPS Hostinger untuk staging/demo** (Nginx + PHP-FPM + PostgreSQL + Redis). Backup: `pg_dump` harian + arsip WAL (pgBackRest) ke penyimpanan terpisah untuk PITR. **Catatan jujur:** target B-01/B-02 sepenuhnya hanya berlaku untuk produksi nyata; di staging portfolio, backup dan uji restore tetap dibuktikan sekali (runbook) tetapi tanpa jaminan RPO 15 menit.

## Konsekuensi
+ Biaya rendah dan sesuai VPS yang sudah ada.
- Operasional (patch, backup, monitoring) ditanggung sendiri.
- Perlu ADR lanjutan bila ada klien nyata (managed DB).

## Pembaruan 6 November 2026
- **Keputusan:** VPS Hostinger tidak dipakai. Server yang cocok ternyata host situs live (`salmanrizwana.com`, 1 vCPU/4 GB); memasang PHP 8.5, PostgreSQL 18, dan Redis di sana berisiko.
- **Gantinya:** staging lokal prod-like di Docker (image produksi, Nginx + PHP-FPM, TLS) lewat `make staging-deploy`. Lihat `docs/runbook-staging.md`.
- **Dampak:** kriteria T0.09 "deploy otomatis ke server" dan "SSL Labs ≥ A" tidak dapat dibuktikan; dicatat sebagai deviasi. Pilihan hosting produksi nyata ditunda sampai ada kebutuhan (ADR baru).
